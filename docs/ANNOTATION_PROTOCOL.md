# Approved-reference detection benchmark

Status: **pending actual human annotation review**. No AP50 or accuracy result is
available. Unit-test AP values demonstrate arithmetic only, not scene performance.
The independent-scene protocol freezes64 test frames per sequence; all64 must be
reviewed, including frames with no selected-category instances. High frame counts
do not imply independent samples. Temporal correlation and small class counts
must appear beside eventual results.

## Access and pilot coverage

ScanNet's official access instructions require an agreement/request. No authorized
subset was confirmed; no restriction was bypassed. TUM archives came from official
publisher URLs, with observed hashes and unchanged original timestamps recorded.
Only16 designated candidate-pilot images per capture were inspected for this
coverage decision. They are disjoint from train, validation and frozen test IDs.

Qualitative pilot inspection found plausible vocabulary overlap: fr1 room shows
laptops, displays, chairs, books, a teddy bear and a person; fr2 desk shows displays,
keyboards, mice, mugs, plants, clocks and teddy bears. Some views show walls, glare
or severe occlusion. This is an AI-assisted qualitative coverage assessment, not
human-verified boxes or quantitative class counts. Fr1 room shares the original
office, and a moving person appears in its pilot: no unseen-site/static-only claim.

Freeze these torchvision COCO category IDs/names for the fallback package:
1/person,44/bottle,47/cup,62/chair,64/potted plant,72/tv,73/laptop,74/mouse,
76/keyboard,77/cell phone,84/book,85/clock,88/teddy bear. Actual approved counts
will determine which categories have defined AP; do not silently invent positives
or report zero for a class with no GT. Unsupported objects remain outside this
vocabulary. A globe is not a sports ball; an office desk is not automatically a
dining table; a landline phone is not a cell phone; a drink can is not automatically
a bottle or cup.

## Label conventions

Use tight boxes around visible physical instances in original RGB coordinates.
Annotate every recognizable instance in the selected vocabulary, including small,
partly occluded and edge-truncated objects. Do not infer hidden box extent. If a
class cannot be resolved confidently, leave the frame unapproved until review;
uncertainty is not an empty negative label. Posters/printed pictures are not
physical instances. Separate laptop devices from standalone displays: do not also
label the laptop's own screen as tv. Potted-plant boxes include pot and foliage;
do not duplicate that pot as a separate vase. A book must be a recognizable bound
book, not loose paper. Crowd regions are only for inseparable same-class groups;
arbitrary ignore boxes are rejected by this evaluator.

The evaluator uses the same approved reference boxes for real and reconstructed
images at the exact same frozen camera poses, resized consistently. Missing
reconstructed objects remain GT positives; do not relabel the render to conceal
reconstruction failures. Keep labels fixed across seeds and policies.

## Review interface and approval

Export a draft review package after validating the dataset:

```bash
UV_CACHE_DIR=$PWD/.cache/uv uv run --frozen python -m simready.annotations.package \
  --scene data/scenes/tum-fr1-room --out artifacts/annotations/tum-fr1-room-v1
python3 -m http.server 8090 --bind 127.0.0.1 \
  --directory artifacts/annotations/tum-fr1-room-v1
```

Open localhost:8090. Packages begin with no boxes and no reviewed frames. The
interface supports drawing or numeric boxes, class selection, crowd regions,
deletion confirmation and draft import/export. Imported drafts reset review
state. Human reviewers must correct/add all instances, explicitly check every
frame, identify themselves, download the current COCO file and affirm personal
review before the approval action becomes available. The approved sidecar binds
the exact downloaded COCO bytes, original dataset manifest and frozen split hash.
Keep both files. It is an explicit reviewer attestation, not a digital identity
certificate. The application cannot independently prove who operated a browser.

Detector proposals, if introduced later, remain drafts and require exhaustive
review; they must never be automatically promoted to GT. No production approval
file is generated by experiment orchestration. Automated UI/unit fixtures are
synthetic implementation tests and never become reviewed scene annotations.

## Evaluation

Install the optional CPU `annotations` extra (pycocotools2.0.11), separate from the
unchanged isolated GPU environment. Run a frozen base-view evaluation first, then:

```bash
UV_CACHE_DIR=$PWD/.cache/uv uv run --frozen --extra annotations \
  python -m simready.annotations.evaluate \
  --scene data/scenes/tum-fr1-room --artifact PATH_TO_MODEL \
  --renders PATH_TO_FROZEN_TEST_RENDERS --evaluation PATH_TO_EVALUATION \
  --annotations PATH_TO_APPROVED_COCO --approval PATH_TO_APPROVAL \
  --out NEW_ACCURACY_OUTPUT_DIRECTORY
```

The gate requires complete test membership, human approval, exact annotation/data/
split hashes, original reference-image hashes, camera dimensions and fixed detector
vocabulary. Missing or mismatched review stops accuracy evaluation; it does not
emit a fake AP number. Scientific render/evaluation binding remains checked.

Use official pycocotools bbox matching and101-point interpolation at IoU0.5,
maxDets100; retain raw fixed-detector outputs (original detector cap300) separately.
Report AP50, macro recall@100, per-class AP/recall/GT counts, and additional TP/FP/FN
and missed objects at score≥0.5. Report rendered-minus-real ΔAP50 with annotation/
image counts and PSNR/SSIM/LPIPS/depth support/error. Macro AP excludes categories
with no GT as undefined, and their counts remain visible. This is bbox evaluation
on a declared COCO-vocabulary subset, not a claim of official COCO leaderboard mAP.
Detector agreement remains a separate learned-output consistency measure.
